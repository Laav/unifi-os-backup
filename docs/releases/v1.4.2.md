# UniFi OS Backup v1.4.2

Compatible patch for installations where the configuration manager rejected literal dollar signs or could not open because dialog was missing.

## Fixes

- The safe parser accepts literal dollars, including a trailing dollar in a double-quoted password. Real variable, command and arithmetic expansion remains refused. Configuration is never sourced/evaluated or automatically rewritten by the manager.
- Syntax diagnostics report only the file basename, line and setting, with values hidden.
- Installer and updater automatically provision missing application dependencies, including dialog and age, using configured APT repositories. No separate apt-install command is required. No wizard launches during an ordinary update, and scheduled backups never install packages.
- Provisioning is idempotent, uses noninteractive APT without requested package removal/distribution upgrade/repository changes, and aborts application deployment with exit 69 on failure. APT may adjust transitive dependencies; package changes are not rolled back. Existing configuration and backups are preserved.

## Upgrade

```bash
cd /opt/unifi-os-backup
git status --short
sudo git fetch origin --tags
sudo git switch --detach v1.4.2
sudo ./update.sh
unifi-backup --version
sudo unifi-backup-configure --validate
sudo unifi-backup-configure
```

Review local modifications before switching; never force a checkout over them. Both install and update support `--no-install-deps` for offline/centrally provisioned hosts. Missing core dependencies then fail, while unavailable optional dialog/age features warn. `sudo ./install.sh --dependencies-only` provisions packages without application deployment. Package repositories and systemd must already be operational.

If the parser still refuses genuine shell expansion, inspect only the indicated location privately and preserve the intended value as a literal assignment. Never share credentials or complete configuration files. No automatic conversion/migration is performed.

For a fresh installation use the inspected bootstrap or pinned checkout in [INSTALL.md](https://github.com/Laav/unifi-os-backup/blob/v1.4.2/docs/INSTALL.md). The bootstrap can provision Git when it is missing.

## Validation and limitations

Regression coverage includes literal-dollar comparison with real Bash, secret-redacted errors, mocked APT success/failure/idempotence/opt-out behavior, real lifecycle scripts preserving configuration/backups, and the existing backup/security/UI tests. Native CI targets Ubuntu 22.04, 24.04 and 26.04. See [validation evidence](https://github.com/Laav/unifi-os-backup/blob/v1.4.2/docs/CONFIGURATION-VALIDATION.md).

APT operations in unit/lifecycle regression tests are mocked. A separate CI integration step uses real APT with the standalone installer's `--dependencies-only` in disposable Ubuntu containers to provision dialog/age. No production configuration, live UniFi/cloud credentials or backup data is used. Real production endpoint compatibility, restoration, cloud permissions and notification delivery still require environment-specific acceptance checks. Existing tags/releases remain unchanged.
