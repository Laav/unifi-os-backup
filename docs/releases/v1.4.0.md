# UniFi OS Backup v1.4.0

**Unpublished source tag, superseded by v1.4.1.** No GitHub Release was published for v1.4.0. The tag is retained unchanged; install [v1.4.1](https://github.com/Laav/unifi-os-backup/releases/tag/v1.4.1), which includes final configuration path-role protection. The notes below are the archived preparation notes, not a publication claim.

A compatible MINOR update from v1.3.0: one secure full-screen terminal configuration experience for the existing backup engine. No mandatory configuration migration or new backup engine is introduced.

## New configuration experience

- `sudo unifi-backup-configure`: optional dialog UI for guided setup, categorized editing, independent storage destinations, notifications, schedule/retention, monitoring and advanced settings, diagnostics and explicit Review/Finish.
- Central declarative schema and a generated 124-row scoped setting inventory: defaults, consumers, validation, dependencies, sensitivity and active/legacy status.
- Offline, noninteractive `--validate`, redacted `--inspect`/`--dry-run`, help/version and generated-reference commands; no TTY or dialog required for these or ordinary backup jobs.
- Safe literal-only parsing/serialization preserves comments and unknown literals. It never evaluates shell expansions, commands, includes or functions; unsupported syntax is refused instead of overwritten.
- Private staged multi-file transactions with dependency fingerprints, configuration/operation locks, durable preimages, automatic signal/error rollback and explicit recovery/rollback after interruption. Cross-file filesystem atomicity is not claimed.
- Narrow manager-owned systemd schedule/config-path/write-access drop-ins retain existing hardening and administrator overrides. Timer activation/restart remains a separate explicit choice.
- Disabled targets can be edited/validated independently. No cloud objects, credentials, provider permissions or private recovery identities are deleted/generated by the wizard. Live login, provider inspection and notification tests are explicitly opt-in.

## Security and compatibility

Sensitive values are masked, never prefilled in dialog, and kept out of process arguments and diagnostic exports. Updated readers hold a configuration read lock before sourcing; hardened services open the pre-created inode read-only. Pending interrupted applies fail closed until recovered. Journals intentionally retain old secrets with private permissions.

Existing manually maintained configurations and scheduled backups do not need the wizard. Separate Graph/storage/ntfy/webhook/recipient/target files remain outside Git. Nonempty `BACKUP_TARGETS` still overrides legacy storage. Switching modes is explicit; disabling the last target cannot silently reactivate dormant legacy storage. Existing enabled integrations/defaults are not reset.

Installer/updater deploy the manager without rewriting existing configuration. `install.sh --configure` explicitly launches it; unattended installation/update needs neither TTY nor dialog. Destination directories are initialized before helper installation, including on minimal environments. Packaged systemd units/timers and backup formats are unchanged.

## Install on a test machine without enabling scheduling

```bash
sudo apt-get update
sudo apt-get install -y git curl python3 coreutils findutils util-linux dialog
sudo git clone --branch v1.4.0 --depth 1 https://github.com/Laav/unifi-os-backup.git /opt/unifi-os-backup
cd /opt/unifi-os-backup
sudo ./install.sh --no-enable --configure
sudo unifi-backup-configure --validate --json
sudo unifi-backup-configure --inspect --json
```

Finish requires explicit confirmation. These commands leave automatic scheduling disabled. Use isolated service accounts/storage/mail destinations and do not choose timer activation in the wizard until acceptance is complete.

## Upgrade an existing installation

```bash
cd /opt/unifi-os-backup
git status --short
sudo git fetch origin --tags
sudo git switch --detach v1.4.0
sudo ./update.sh
unifi-backup --version
unifi-backup-configure --version
sudo unifi-backup-configure --inspect --json
sudo unifi-backup-configure --validate --json
```

Review local changes before switching. The updater installs the checked-out source; it does not independently select/download a release. Allow jobs started by older binaries to finish before the first configuration transaction. Existing configuration, keys, backups, catalog and monitoring data are preserved. Install dialog explicitly only if the UI is wanted. No automatic storage conversion is required.

When ready, deliberately test `sudo unifi-backup-check --live`, create one backup, inspect journald and run `sudo unifi-backup-verify --latest --json`. These live steps are not run by installation or Finish. A changed active schedule needs an explicit timer restart; starting a Persistent timer may immediately run an overdue job.

## Recovery, rollback and limitations

Use `sudo unifi-backup-configure --recover --yes` for a pending apply or `--rollback TRANSACTION_ID --yes` for a completed configuration transaction; custom main paths need the same `--config` argument. Never delete the pending marker to bypass recovery. Later operator edits/corrupt preimages cause safe refusal. Private journals require credential-grade protection and retention.

Before an application rollback to v1.3.0, finish/recover pending transactions, stop conflicting activity, preserve journals/configuration, disable the newer manager entry point and review its owned drop-ins. Older readers do not participate in configuration locking. See [UPGRADING.md](https://github.com/Laav/unifi-os-backup/blob/v1.4.0/docs/UPGRADING.md).

The safe parser supports bounded UTF-8 literals, not arbitrary Bash; unsupported existing expressions need a private backup and manual conversion before manager editing. The UI is not a multiline secret editor, though existing multiline literals round-trip safely. Independent installations/manual editors/old readers require external coordination. Config rollback does not undo separate timer-activation actions. Later administrator drop-ins can override manager choices.

Automated validation covers the Bash suite, Python security/rollback tests, real Linux dialog pseudo-terminals, lifecycle-script sandbox, real age, permissions/symlinks/locks, generated systemd drop-ins, installed CLI/reference checks, ShellCheck and the Ubuntu 22.04/24.04/26.04 matrix. Exact evidence is recorded in [CONFIGURATION-VALIDATION.md](https://github.com/Laav/unifi-os-backup/blob/v1.4.0/docs/CONFIGURATION-VALIDATION.md).

All 67 Python cases and all 16 Bash scripts passed without skips in each Ubuntu matrix environment for the validated implementation. Final release-source/tag CI is a separate publication gate. CI uses x86-64 containers; native ARM64 and a visual walkthrough on your own SSH terminal still need acceptance testing.
