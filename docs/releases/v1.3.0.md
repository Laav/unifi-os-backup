# UniFi OS Backup v1.3.0

A compatible MINOR release extending backup creation into verifiable replication and recovery preparation. This is the first GitHub Release: the preceding source version was 1.2.0 and origin had no previously published tags/releases when verified.

## New functionality

- Repeated local metadata, size and SHA256 checks through `unifi-backup-verify`, with optional real age decryption and explicit limited structure/untested restore outcomes.
- Independent Azure Blob, S3-compatible and mounted-filesystem targets, per-target results, required destinations and a remote-success quorum.
- Shared conditional upload, listing, HEAD, download and full downloaded-byte verification, plus persistent bounded retries, jittered backoff, dead letters and retention pins.
- Read-only immutability capability/policy inspection and explicitly configured new-object retention requests with post-upload confirmation. No automatic holds, unlocks, remote deletion or bucket-policy changes.
- Optional GFS retention with dry-run keep/delete explanations.
- Local/remote disaster recovery discovery, integrity validation, optional decryption and private file preparation with a machine-readable report.
- Deterministic size/timing/failure anomaly analysis, optional identical plaintext-hash warnings and bounded local history.
- Privacy-preserving normalized configuration-export diffs. Native opaque `.unifi` semantic extraction remains explicitly unsupported.

## Security and compatibility

Existing settings and default age/count/minimum retention remain supported. Nonempty `BACKUP_TARGETS` overrides legacy remote settings, preventing duplicate uploads. New automatic operations default off. Local valid creation is recorded independently from remote policy failure. Retention-only mode now uses the shared operation lock. Webhook secret URLs no longer appear in Python arguments.

No recovery command changes a live controller. Hashes/metadata are not independent authenticity proofs; use protected manifests and conduct isolated restore drills. Immutability capability varies by provider and permissions; permanent compliance/locked requests need explicit configuration. No cloud protection is silently downgraded.

## Upgrade

```bash
cd /opt/unifi-os-backup
git status --short
sudo git fetch origin --tags
sudo git switch --detach v1.3.0
sudo ./update.sh
unifi-backup --version
sudo unifi-backup-check --live
sudo systemctl start unifi-backup.service
sudo unifi-backup-verify --latest --json
```

Review local modifications before switching. `update.sh` installs the checked-out source; it does not choose/fetch a release. Configuration, backups and keys are preserved. The existing main-branch `git pull --ff-only` workflow is retained.

Review `config/unifi-backup.env.example` and `config/target.env.example`. Enable `VERIFY_ENABLED`, `REMOTE_VERIFY_ENABLED`, `RETRY_ENABLED`, `ANOMALY_ENABLED` or `DIFF_ENABLED` only when needed. Verify/remote-verify/retry timers are installed disabled and must be activated explicitly. Additional storage read/list/immutability permissions are needed for the new capabilities; legacy upload behavior retains its existing requirements.

Rollback instructions, including the verified preceding source commit where no older release exists, are in [UPGRADING.md](https://github.com/Laav/unifi-os-backup/blob/v1.3.0/docs/UPGRADING.md). Do not use old retention against backups pinned by active new retry tasks.

## Validation and known limitations

The release is gated by the Bash regression/integration suite, standard-library Python tests, real age tests, ShellCheck, privacy review and the Ubuntu 22.04/24.04/26.04 CI matrix including systemd unit checks. Cloud protocols are mocked; no live Azure/S3 credentials, provider WORM mutations, production UniFi restore, actual Auvik/RMM agent or Graph delivery is claimed as tested by this release.

`.unifi` structure validation remains limited; decryption success never means restore-tested. Configuration diffs require explicitly normalized, hash-bound exports from an independently reviewed extraction process; arbitrary native archives are rejected. Retry timing/limits are installation-wide while each task retains its own target, due time and attempt count. Queue limits and dead-letter expiry protect against unlimited retention pins but require operational monitoring. Filesystem targets require a trusted private directory/marker and a mount by default.
